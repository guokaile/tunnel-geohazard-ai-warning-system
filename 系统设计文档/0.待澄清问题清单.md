## A组 业务范围与监测对象

**Q1. 监测对象**：坍塌（围岩失稳/冒顶/塌方）、涌水/突水、瓦斯及有害气体（CH₄/CO/H₂S）、突泥、地表沉降/拱顶下沉、围岩收敛位移、岩爆、结构应力——本期覆盖哪些？
⭐建议默认：前 6 类全覆盖（与背景描述一致），岩爆/应力视地质条件可选。

**Q2. 建设阶段覆盖**：A.仅施工期；B.仅运营期；C.施工+运营全周期。
⭐建议默认：C，数据模型与预警体系按全周期设计，施工期先行。

**Q3. 项目规模**：拟接入隧道条数、监测断面数、监测点位总量级（百/千/万）、在线用户量级。
⭐建议默认：按 1~3 条隧道、1000~5000 点位、≤50 并发用户设计，预留水平扩展能力。

**Q4. 行业规范与制度**：是否必须对标 JTG/T 3660—2020《公路隧道施工技术规范》、TB 10120—2019《铁路瓦斯隧道技术规范》、GB/T 22239—2019《网络安全等级保护》？有无甲方/集团内部监测预警制度文件需遵循？
⭐建议默认：按公路/铁路隧道相关规范 + 等保二级设计。

## B组 数据来源与接入

**Q5. 传感器IoT**：现场是否已部署传感器？厂商/型号/通信协议（RS485/Modbus、LoRa、NB-IoT、TCP 自定义、MQTT）？采集频率与点位规模？是否已有采集网关/平台可对接，还是本系统直采？
⭐建议默认：由现场采集网关汇聚后以 TCP/MQTT 统一上送本系统，频率 1 次/30s~5min（按测项可配）。

**Q6. 人工巡检**：现成巡检表单（巡检项/频次/格式）？录入方式（PC/移动端）？
⭐建议默认：系统内置电子巡检台账（巡检模板可配置），PC + 移动 H5 录入，每班/每日一次。

**Q7. 第三方系统**：需对接哪些系统（瓦斯监控系统、超前地质预报、视频监控、气象、业主/集团平台等）？对接方式（REST API/库表/文件/消息推送）？
⭐建议默认：本期预留标准 REST 对接接口 + 文件导入兜底。

**Q8. 历史台账**：是否有历史监测数据、灾害事件记录可用于数据导入与算法训练？格式（Excel/旧数据库）与量级（条数/年数）？
⭐建议默认：若无可训练样本，算法一期采用规则+统计模型（见 Q17）。

## C组 用户角色与组织

**Q9. 角色确认**：现场监测员、值班调度员、管理领导、系统管理员是否齐全？是否增加"技术专家（预警研判）"角色？
⭐建议默认：4+1 共 5 类角色。

**Q10. 组织层级**：单项目独立部署，还是"集团—项目"两级（数据上报/监管）？
⭐建议默认：单项目独立部署，预留数据上报接口。

**Q11. 登录认证**：本地账号密码 / 对接 AD·LDAP / 钉钉·企业微信扫码？
⭐建议默认：本地账号 + RBAC 权限（满足等保），预留 OAuth2 扩展。

**Q12. 账号规模**：用户总量与同时在线量级？
⭐建议默认：≤200 账号、≤50 并发。

## D组 预警分级与响应

**Q13. 蓝黄橙红响应动作**：是否有甲方既有预警制度文本？若无，是否接受按行业惯例给出完整映射表（蓝=关注：值班查看跟踪；黄=警戒：加密监测+现场核查；橙=处置：停工撤人+专家会商；红=紧急：全线撤离+启动应急预案；含动作、时限、上报层级），评审时定稿？
⭐建议默认：接受，按惯例定义。

**Q14. 通知渠道**：现场声光报警联动、短信、APP/微信推送、电话语音、邮件——哪些本期必做？短信网关供应商（阿里云/腾讯云/运营商）是否已定？
⭐建议默认：声光报警联动 + 短信 + 站内/APP 推送本期必做；电话/邮件二期；短信网关待定。

**Q15. 预警处置闭环**：是否要求"预警生成→值班确认→派单处置→现场反馈→复核消警"全流程闭环与全程留痕？
⭐建议默认：需要，作为值班调度核心功能。

## E组 AI算法能力

**Q16. 算法范围**：①阈值/速率规则预警（必须）②时序趋势预测与突变检测 ③多源数据综合研判（多指标联动定级）④视频图像识别（AI 视觉）——本期范围？
⭐建议默认：①+②+③ 本期，④ 列入二期规划。

**Q17. 训练数据**：是否有带标签的历史灾害/预警事件数据可用于模型训练？
⭐建议默认：无→一期采用规则引擎+统计模型（滑动窗口、突变检测、趋势拟合），上线后积累数据迭代 ML 模型；如有请提供数据说明。

**Q18. 算力环境**：部署服务器是否配置 GPU？
⭐建议默认：按无 GPU 设计（轻量模型、CPU 推理，秒级~分钟级计算可满足）。

## F组 部署、性能与安全

**Q19. 部署环境**：目标服务器操作系统与规格（CPU/内存/磁盘）？隧道现场网络条件（内网/离线/有公网）？
⭐建议默认：Windows Server 2022、8C16G、单机一体化部署（后端+Nginx+MySQL 同机），支持完全离线安装。

**Q20. 性能指标**：预警判定延迟、数据入库吞吐、页面响应要求？
⭐建议默认：数据入库→预警判定延迟 ≤30s（突发类事件 ≤10s）、日入库 ≥100 万条、查询页面 P95 ≤3s。

**Q21. 数据保留**：原始采样、聚合数据、预警事件记录保留周期？
⭐建议默认：原始 1 年（可归档）、分钟级聚合 3 年、预警与处置记录永久。

**Q22. 安全合规**：是否需要过等保测评（二级/三级）？是否需要操作审计日志与数据库自动备份？
⭐建议默认：按等保二级要求设计（三级可平滑升级）、全操作审计 + 每日自动备份。

## G组 交付与验收

**Q23. 前端交付**：是否由本项目一并交付 Web 前端？技术栈偏好（Vue3/React）？是否需要移动端（H5 自适应 or 独立 APP）？
⭐建议默认：Vue3 + PC Web + 移动 H5 自适应，一并交付。

**Q24. 安装包形态**：exe 安装向导 or 免安装绿色版？JDK/MySQL 是否随包内置？
⭐建议默认：exe 向导式安装包，内置 JDK25 + MySQL 绿色版 + 一键初始化脚本（此条亦可推迟至阶段2定稿）。

**Q25. 验收口径**：试运行周期、验收标准与评审形式？
⭐建议默认：现场试运行 ≥30 天，按阶段8《测试计划》执行并出具测试报告，功能演示 + 文档交付评审。
