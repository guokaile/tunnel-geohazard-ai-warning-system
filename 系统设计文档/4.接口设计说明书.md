## 4.2 REST API 规范总则

| 规范项 | 约定 |
|---|---|
| 路径风格 | `/api/v1/{业务域}/{资源}`，资源用复数名词，动作用 HTTP 方法表达（RESTful） |
| 统一响应 | `{"code":"00000","message":"success","data":{...},"timestamp":1758643200000}`；`code` 为字符串 5 位错误码 |
| HTTP 状态码 | 业务成功恒 200；401 未认证/令牌无效、403 无权限、404 资源不存在、429 限流、500 系统异常 |
| 分页 | 入参 `pageNum`（≥1）、`pageSize`（1~200）；出参 `{"total":100,"list":[...]}` |
| 排序 | `orderBy=field:asc|desc`，白名单校验防注入 |
| 时间 | 接口展示统一 `yyyy-MM-dd HH:mm:ss`（秒级）；**采集通道与库内为毫秒**（data_sample.ts 为 datetime(3)）；时序类接口返回可选 `tsMillis` 毫秒字段（同秒排序/去重用） |
| 数值 | 监测值/金额用 JSON number（后端 decimal(16,4) 序列化，前端控制展示精度） |
| 鉴权 | `Authorization: Bearer {token}`；**access 30min + refresh 2h（滑动），refresh 每次轮换、旧 refresh 立即失效**；登出令牌进 Caffeine 黑名单（TTL 30min；单机重启黑名单丢失可接受）；权限点校验见 4.7 |
| 幂等 | 创建类接口请求头 `Idempotency-Key`（UUID），后端 24h 窗口内同键返回首次结果 |
| 防重放 | 请求头 `X-Ts`（毫秒时间戳）+ `X-Nonce`（随机串），5min 窗口+nonce 缓存校验 |
| 文件上传 | multipart/form-data；图片 jpg/png ≤5MB；文件名服务端重命名（雪花+扩展名），禁止原始文件名落盘 |
| 国际化 | 接口与错误码文本以中文为准，错误码作为程序判据（前端按 code 映射提示） |

## 4.4 外部接口协议设计

### 4.4.1 TCP 采集协议（网关→系统，Netty :9000）

**帧结构（大端序）**：

| 字段 | 长度 | 说明 |
|---|---|---|
| SOF | 2B | 帧头 `0xAA 0x55` |
| LEN | 2B | 帧长度 = TYPE 字段首字节至 ITEMS 末字节的字节数（**不含 SOF/LEN/CRC16**），范围 [19, 65535] |
| TYPE | 1B | 0x01 实时数据 / 0x02 心跳 / 0x03 补传数据 / 0x04 注册请求 / 0x10 ACK |
| GW_ID | 8B | 网关编号 ASCII，右补 0x00（对应 mon_gateway.gateway_code） |
| TS | 8B | **Unix 毫秒时间戳**（UTC，int64，支撑同秒去重；**单位与 data_sample.ts datetime(3) 对齐，T-902a 协议确认材料醒目单列——厂商最易按"秒"误实现**） |
| N | 2B | 数据点数（心跳为 0；上限 1024） |
| ITEMS | N×变长 | 数据块：**点位编码长度 1B + 点位编码 ASCII（≤32 字节，字符集 [A-Z0-9-]） + 质量位 1B + 值 8B（int64 缩放整数）** |
| CRC16 | 2B | MODBUS CRC16（TYPE 至 ITEMS 末，低字节先发） |

**值编码**：`实际值 = 整数 × 10^-scale`，scale 全局可配（sys_config，默认 4，与 mon_point.scale 一致）。采用**整数缩放而非 float**：无损映射 decimal(16,4)、判定与留痕同一数值、可精确复算（工业协议通行做法）。量程与标定信息存 mon_point（range_min/range_max/scale），换传感器后更新台账即可。

**组帧与解析规则（LEN 是帧边界识别的唯一依据）**：

```
1. 接收方先读满 4 字节（SOF+LEN），校验 SOF=0xAA55，否则逐字节滑动重同步；
2. 按 LEN 取满整帧（半包等待补齐，10s 收包超时）；
3. 校验 CRC16（TYPE 至 ITEMS 末），失败则丢弃+计数告警，并继续扫描下一个 0xAA55（防错帧粘包）；
4. 校验通过 → 分派处理（数据/心跳/补传/注册）。
```

**边界用例（联调必测）**：①半包（先收 10 字节再收余下）②粘包（一次收 3 帧）③CRC 错帧后紧跟正确帧 ④N=0 心跳帧（LEN=19）⑤超长帧（N>1024 或 LEN 超限 → 断连告警）。

**行为约定**：心跳 60s/次，180s 无心跳判离线；补传帧（0x03）在重连后优先发送，幂等由**两层保证**：应用侧 `(point_id, ts)` 近 48h 窗口去重 + **数据库主键 `(point_id, ts)` 兜底**（批次写入 `ON DUPLICATE KEY UPDATE` 幂等覆盖，重启后 48h 内重连补传不产生重复行）；**迟到数据（ts 晚于当前 10min）正常入库并参与聚合/模型基线，但不触发实时预警**（防补传引发历史性误报）；单连接限速 100 帧/秒，超限断开；CRC 失败丢弃并计数告警。

**网关注册流程（首次入网）**：网关连接后发送 0x04 注册帧——N=1，数据块为**凭据项**：PC 字段填 `HMAC-SHA256(PSK, GW_ID+TS) 的 HEX 前 32 字符`，Q=0，VALUE=协议版本号×10^scale。系统按 mon_gateway.secret 计算比对（PSK 安装部署时预置，密文存储），**并校验时间戳新鲜度（±5min 防重放窗口，sys_config `protocol.register_window_sec` 默认 300，超窗回结果码 6 并断开——防注册帧原样重放；现场调试期可临时放宽）**；校验通过回 ACK（结果码 0，附带服务器时间戳用于授时）；失败回对应结果码并断开。**网关应以 ACK 授时校准本地时钟，后续所有帧的 TS 使用校准后的毫秒**。**scale、心跳周期等参数在部署阶段配置于网关侧，协议仅确认版本与授时**；协议版本在注册帧 VALUE 字段中协商（TYPE 字节完整使用，不预留版本位）。

**ACK 帧（0x10）**：N=1，数据块 PC 固定填 `"RSP"`（ASCII），Q=结果码（0 成功 / 1 CRC 错误 / 2 网关未注册 / 3 点位未配置 / 4 凭据错误 / 5 版本不支持 / **6 时间戳超窗（防重放）**），VALUE=服务器时间戳（ms）。逐字节自洽的完整报文示例与解析伪代码见附录A。

### 4.4.2 MQTT 主题与载荷（网关→系统，内嵌 Moquette :1883）

| 主题 | 方向 | 说明 |
|---|---|---|
| `tgaws/v1/gateway/{gwId}/data` | 网关→系统 | 数据上报（QoS 1） |
| `tgaws/v1/gateway/{gwId}/heartbeat` | 网关→系统 | 心跳（QoS 1） |
| `tgaws/v1/gateway/{gwId}/retrans` | 网关→系统 | 补传（QoS 1） |
| `tgaws/v1/cmd/{gwId}` | 系统→网关 | 下行指令（预留，QoS 1） |

**载荷 JSON**：`{"gw":"GW001","ts":1790301600123,"items":[{"pc":"P00010001","q":0,"v":"12.3456"}]}`——`ts` 为 Unix **毫秒**；`v` 为**十进制字符串**（任意精度无损，与库内 decimal(16,4) 严格一致，避免 JSON number 双精度损耗）。鉴权：clientId=网关编号，账号 `${MQTT_USERNAME}`/`${MQTT_PASSWORD}`；未注册 clientId 拒绝连接。迟到数据与 TCP 通道同一规则（10min 窗口只入库不判定）。**协议版本声明（T3 结论）**：内嵌 Moquette 0.17 支持 **MQTT 3.1.1，不支持 MQTT 5.0**——网关设备须按 3.1.1 实现；若厂商设备仅支持 5.0，触发架构 2.11 外置 Broker 切换评估。

### 4.4.3 第三方系统推送接口（FR-105，Open API）

**POST /open/v1/data/push**（瓦斯监控系统等第三方→本系统）

| 项 | 约定 |
|---|---|
| 请求头 | `X-App-Key`、`X-Timestamp`（毫秒）、`X-Nonce`、`X-Sign` |
| 签名 | `X-Sign = HMAC-SHA256(appSecret, timestamp + nonce + METHOD + PATH + body)`，Hex 小写（纳入方法与路径，防跨接口重放） |
| 校验 | 时间窗 5min（防重放）、nonce 24h 唯一、appKey 在 sys_third_app 注册且启用、**来源 IP 在应用白名单内** |
| 请求体 | `{"batchNo":"TP20260925001","items":[{"pointCode":"P00010001","ts":"2026-09-25 10:00:00","value":12.5,"quality":0}]}` |
| 响应体 | `{"code":"00000","message":"success","data":{"received":100},"timestamp":...}` |
| 限流 | 单 app 100 请求/分钟，超限 429 |
| 密钥管理 | appSecret 密文存储（sys_third_app），支持轮换（新旧密钥并行 24h 过渡窗口） |

### 4.5.7 核心接口详细定义（12 个代表接口）

**1) POST /api/v1/auth/login**

请求：`{"username":"disp01","password":"******"}`（占位）
响应：`{"code":"00000","message":"success","data":{"token":"eyJ...","refreshToken":"eyJ...","expiresIn":7200,"user":{"id":1,"username":"disp01","realName":"张三","roles":["DISPATCHER"],"permissions":["warn:event:view","warn:event:confirm",...]}},"timestamp":1758643200000}`
错误码：C0002 用户名或密码错误（不区分账号是否存在，防用户枚举）/ C0003 账号锁定（第 5 次失败即返回）/ C0004 账号停用 / C0005 密码过期

**2) GET /api/v1/mon/latest**（看板核心，Caffeine 缓存 5s）

入参：`tunnelId、sectionId、hazardType、keyword、pageNum、pageSize`
响应：`{"total":5000,"list":[{"pointId":101,"pointCode":"P00010001","pointName":"K1+200拱顶位移","hazardType":1,"itemType":101,"unit":"mm","value":12.35,"ts":"2026-09-25 10:00:00","quality":0,"onlineStatus":1,"warnLevel":0}]}`
（warnLevel=0 无预警，1~4 当前级别）

**3) GET /api/v1/mon/points/{id}/series**

入参：`start=2026-09-24 00:00:00&end=2026-09-25 00:00:00&granularity=raw|minute`（raw 限 7 天跨度，超限自动降级 minute 并返回 granularity 字段）
响应：`{"pointId":101,"granularity":"raw","series":[{"ts":"...","value":12.3,"quality":0},...]}`（单次 ≤10000 点，超限分页 cursor）

**4) POST /api/v1/warn/events/{id}/confirm**

入参：`{"result":1,"conclusion":"瓦斯浓度超限属实，已通知现场"}`（result=2 表示误报，conclusion 必填）
校验：事件状态=1（待确认）；result=2 → 状态 6（误报关闭）；result=1 → 状态 2（已确认）
响应：事件最新状态+时间线增量；错误码 B0302 状态不允许

**5) POST /api/v1/warn/events/{id}/close**

入参：`{"reason":"CH4浓度回落至0.1%以下并稳定2小时，现场核查无异常"}`
校验：状态=4（待复核）+ 当前用户角色含复核权限（值班调度/技术专家）；reason 必填（B0304）
响应：状态=5（已消警）+ closeTime/closeUser

**6) POST /api/v1/warn/tasks**

入参：`{"eventId":1001,"assigneeId":8,"measure":"停止该断面作业，加密监测并核查掌子面渗水情况","deadline":"2026-09-25 18:00:00"}`
校验：事件状态=2/3；assignee 为监测员/调度；事件转入处置中(3)
响应：`{"taskNo":"RW20260925001","status":1}`

**7) POST /api/v1/warn/tasks/{id}/feedback**（multipart）

表单：`content=现场已停止作业，渗水量约3L/s&images=[文件]`
校验：任务状态 1/2 且当前用户=责任人；分次反馈均记录 warn_dispose_feedback

**8) GET /api/v1/warn/events/{id}/timeline**

响应：`{"eventNo":"WJ20260925001","timeline":[{"time":"2026-09-25 02:00:05","type":1,"actor":"系统","action":"生成黄级预警","detail":"CH4浓度0.52%超阈值"},{"time":"02:00:08","type":2,"actor":"系统","action":"短信通知","detail":"值班调度张三、监测员李四"},{"time":"02:03:12","type":3,"actor":"张三","action":"确认预警","detail":"..."},...]}`

**9) POST /api/v1/patrol/tasks/{id}/records**（multipart，移动端核心）

表单：`items=[{"itemId":31,"result":1,"description":""},{"itemId":32,"result":2,"description":"边墙局部渗水"}], images=[文件]`
校验：任务状态 1/2 且当前用户=巡检人；result=2（异常）自动提示登记隐患（不强制）

**10) GET /api/v1/rpt/dashboard**

响应：`{"todayWarnCount":12,"todayUnclosed":3,"closeRate":0.87,"pointOnlineRate":0.96,"highRiskPoints":[{"pointCode":"P00020031","level":3}],"weekTrend":[{"date":"2026-09-19","count":8},...]}`

**11) POST /open/v1/data/push**（第三方，签名见 4.4.3）

响应：`{"code":"00000","message":"success","data":{"received":100,"failed":2},"timestamp":...}`
错误码：A0004 签名无效（含缺头/nonce 重放/未注册/停用/过期/IP 白名单外——统一拒绝防枚举）/ A0005 请求时间超窗（5min）；限流超限 HTTP 429

## 4.8 接口安全设计

| 措施 | 实现 |
|---|---|
| 认证 | JWT（HS256，密钥 `${JWT_SECRET}` 环境变量）；access 30min/refresh 2h 滑动+轮换；登出令牌进 Caffeine 黑名单（TTL 30min，单机重启丢失可接受） |
| 授权 | 权限点注解校验（AOP）+ 数据权限（DataScopeHelper 显式条件构建 + Mapper 签名强制携带，见 4.7 与详细设计 6.3.6） |
| 传输 | Nginx 终结 TLS（证书可配）；内网 HTTP 降级需显式配置 |
| 防注入 | MyBatis 参数化预编译；orderBy 白名单；like 特殊字符转义 |
| 防爆破 | 登录 IP+账号双维度限流（5 次/分钟），失败锁定 |
| 防重放 | X-Ts + X-Nonce + 签名（Open API 为 HMAC-SHA256） |
| 限流 | 全局限流（429）；Open API 单应用 100 请求/分钟 |
| 敏感数据 | 响应日志脱敏（password/token/secret 掩码）；审计日志入参脱敏落库 |

## 4.9 接口版本与兼容策略

1. 路径版本 `/api/v1`，破坏性变更升 `/api/v2` 并保留 v1 两个版本周期；
2. 兼容原则：新增字段不动旧字段语义；删除字段先标记 deprecated 一个版本；枚举仅追加不重用数值；
3. Open API（第三方/上报）另行携带 `X-Api-Version` 头，独立演进；
4. TCP/MQTT 协议版本：**在注册帧 VALUE 字段中协商**（TYPE 字节完整使用，不预留版本位，与 4.4.1 帧定义一致），变更需网关厂商联调确认；
5. 内部接口：模块内自由演进，跨模块接口变更需评审并同步调用方。

## 附录A 报文与请求示例

**A.1 TCP 实时数据帧（十六进制，1 条数据，逐字节自洽）**

完整帧（44 字节，已按 4.4.1 定义逐字节核算，含真实 CRC16 计算值）：

```
AA 55 00 26 01 47 57 30 30 31 00 00 00 00 00 01 A0 D6 4A 79 00 00 01 09 50 30 30 30 31 30 30 30 31 00 00 00 00 00 00 01 E2 40 53 7D
```

逐字节拆解：

| 字节 | 字段 | 值 | 说明 |
|---|---|---|---|
| AA 55 | SOF | — | 帧头 |
| 00 26 | LEN | 38 | TYPE..ITEMS 共 38 字节（0x0026） |
| 01 | TYPE | 0x01 | 实时数据 |
| 47 57 30 30 31 00 00 00 | GW_ID | "GW001" | ASCII 右补 0x00 |
| 00 00 01 A0 D6 4A 79 00 | TS | 1790301600000 | Unix ms = 2026-09-25 10:00:00 (UTC+8) |
| 00 01 | N | 1 | 1 个数据块 |
| 09 | PC_LEN | 9 | 点位编码长度 |
| 50 30 30 30 31 30 30 30 31 | PC | "P00010001" | ASCII |
| 00 | Q | 0 | 质量位正常 |
| 00 00 00 00 00 01 E2 40 | VALUE | 123456 | int64 缩放整数 = 12.3456×10⁴（scale=4） |
| 53 7D | CRC16 | 0x7D53 | MODBUS CRC16 低字节先发（覆盖 TYPE..ITEMS） |

**解析伪代码（半包/粘包/错帧处理）**：

```
buffer.append(bytes)
loop:
  if buffer.size < 4: break
  if buffer[0..1] != 0xAA55: buffer.removeFirst(); continue   # 重同步
  len = bigEndian16(buffer[2..3])
  if len < 19 or len > 65535: buffer.removeFirst(); countBadFrame++; continue
  if buffer.size < 4 + len + 2: break                          # 半包等待
  frame = buffer[0 .. 4+len+2)
  if crc16modbus(frame[4 .. 4+len]) != frame[4+len .. 4+len+2):  # CRC 错帧
      buffer.removeFirst(); countBadFrame++; continue
  dispatch(frame); buffer.remove(4+len+2)                      # 粘包循环继续
```

**边界用例（联调必测）**：①半包（先收 10 字节再收余下）②粘包（一次收 3 帧）③CRC 错帧后紧跟正确帧 ④N=0 心跳帧（LEN=19）⑤超长帧（N>1024 → 断连告警）。

**A.2 MQTT 载荷示例**（主题 tgaws/v1/gateway/GW001/data）
